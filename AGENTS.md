# Mnemograph Workbench Governance

## Repository Purpose

Mnemograph Triadic Research Workbench is the repository scope. Current work is repository foundation, not Mnemograph_Core business logic. The normative inputs are the accepted Project Charter v1.2 and System Design v0.1 under docs/baseline.

## Normative Hierarchy

Highest to lowest authority:

1. accepted baseline documents
2. accepted ADRs
3. human-approved issue and implementation plan
4. source code and tests
5. generated artifacts

Copilot must not modify normative documents or reinterpret lower-level artifacts as authority over them.

## Human Supervision

- Work in small reviewable batches.
- Stop after each approved batch for human review.
- Never commit, push, merge or open a PR unless explicitly instructed.
- Never amend or rewrite an already reviewed commit.
- Stop on scope, dependency, security or normative ambiguity.
- Preserve unrelated user changes.

## Dependency Governance

- Exact direct dependency pins only.
- Never add, remove or upgrade a direct dependency without explicit approval.
- Lockfiles are generated by package managers and never hand-edited.
- Transitive dependency changes must be reviewed through lockfile diffs.
- pnpm allowBuilds must remain an explicit minimal allowlist.
- Existing approved build-script allowlist: sharp and unrs-resolver only.
- Compose images are pinned and are replaceable local adapters only.

## Dependency Boundaries From System Design 11.1

- domain imports no web framework, database client or model SDK.
- api and worker use domain/application ports when those layers exist.
- model_gateway contains no domain decisions.
- prompts are versioned and tested as source code.
- web consumes published API contracts only.
- publication must not invoke providers outside Model Gateway.

## Phase 0 Operational-Placeholder Exception

The only current runtime behavior is:

- web static placeholder page
- API GET /health
- worker deterministic readiness line

No other business behavior may be introduced in Phase 0.

## Never Delegate To Copilot

- changing normative requirements
- selecting a model provider without an ADR
- adding an unapproved dependency
- bypassing or weakening tests
- destructive migration or data deletion
- enabling unrestricted Autopilot
- committing secrets
- treating AI output as scientific evidence
- publishing copyrighted source documents
- silently resolving Scientist/SA disagreements

## Required Quality Gate

- pnpm install --frozen-lockfile
- uv sync --all-packages --locked
- pnpm run validate
- docker compose config for Compose changes
- relevant focused tests before the full gate
- git diff --check excluding immutable baseline documents

## Nested AGENTS.md Convention

- Nested files may be added later when bounded modules have local invariants.
- The nearest applicable AGENTS.md takes precedence.
- A nested file may strengthen but not weaken root governance.
